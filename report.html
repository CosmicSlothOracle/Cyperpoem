1. Executive Summary

Purpose

This report details the perimeter vulnerability assessment of host 10.10.10.130. Our objective was to evaluate the exposed attack surface, map the running configurations, and provide actionable security recommendations to strengthen the infrastructure boundary.

Overall Posture

The system displays critical defensive gaps. Port scanning discovered two open TCP services (SSH on port 22 and HTTP on port 80). The web interface exposes active backdoors/test scripts inside an indexable /test/ directory. Specifically, an unauthenticated web shell (/test/shell.php) was confirmed, allowing complete, unauthorized system access. In addition, the underlying web server (lighttpd/1.4.28) and the SSH daemon (OpenSSH 5.9p1) are severely outdated, introducing critical vulnerability vectors.

Consolidated Findings

  • F-01: Exposed Web Shell (TCP/80) – Active backdoor endpoint identified at /test/shell.php. Accepts remote system command parameters. [CRITICAL]
  • F-02: Web Directory Indexing Enabled (TCP/80) – Directory listing enabled on /test/, exposing critical backend scripts (shell.php, revs.php). [HIGH]
  • F-03: Outdated Web Daemon (TCP/80) – Operating lighttpd/1.4.28. End-of-life server susceptible to direct host exploitation. [HIGH]
  • F-04: Outdated & Vulnerable SSH Suite (TCP/22) – Running OpenSSH 5.9p1 on Debian. Susceptible to user enumeration (CVE-2016-6210, CVE-2018-15473) and weak KEX negotiation. [MEDIUM]
  • F-05: Missing HTTP Transport Protections (TCP/80) – The web service transmits data in plaintext without SSL/TLS, and lacks critical security headers (CSP, HSTS, X-Frame-Options). [MEDIUM]
  • F-06: Unauthenticated Diagnostic Endpoints (TCP/80) – /test/revs.php triggers 500 internal errors on targeted parameters, indicating active diagnostic/log exposure. [MEDIUM]

NOTE: Audit Limitations

  • No active brute-forcing or credentials spray succeeded on SSH port 22.
  • No active network database ports (MSSQL/1433, Oracle/1521) or printer services (9100) are open.
  • Network boundary testing verified a default Linux initial TTL of 64 on syn-ack handshakes.

2. Scope & Technical Methodology

Technical Scope: Non-destructive network analysis against 10.10.10.130. Services were probed using synchronized port sweeps, protocol-specific handshakes (SSH/HTTP), and directory fuzzing tools. Exploitation of the discovered web shell backdoor was intentionally avoided to comply with lab rules.

Tools Leveraged: nmap, naabu, ffuf, nuclei, and targeted protocol analyzers.

4.2 Custom Python Banner Prober Tool

import asyncio
import json

TARGET = "10.10.10.130"
PORTS = [21, 22, 80, 1080, 3389]

async def probe(port: int):
    result = {"port": port, "open": False, "banner": ""}
    try:
        reader, writer = await asyncio.wait_for(asyncio.open_connection(TARGET, port), timeout=4)
        result["open"] = True
        probes = [b"", b"HEAD / HTTP/1.0\r\nHost: 10.10.10.130\r\n\r\n", b"\r\n"]
        data = b""
        for p in probes:
            if p:
                writer.write(p)
                await writer.drain()
            try:
                chunk = await asyncio.wait_for(reader.read(1024), timeout=3)
            except Exception:
                chunk = b""
            if chunk:
                data = chunk
                break
        writer.close()
        await writer.wait_closed()
        if data:
            result["banner"] = data.decode("utf-8", errors="replace").strip()
    except Exception:
        pass
    return result

async def main():
    results = await asyncio.gather(*[probe(p) for p in PORTS])
    print(json.dumps(results, indent=2))

if __name__ == "__main__":
    asyncio.run(main())

5. Action Items & Security Recommendations

Priority P0 – Critical System Remediation

  • Remove Backdoors: Instantly delete shell.php, revs.php, and any files from the /test/ directory.
  • Disable Directory Indexing: Alter web server configuration to globally forbid directory indexing (set dir-listing.activate = "disable" in lighttpd configuration).
  • Restrict Access: Place testing environments completely behind internal firewalls or VPNs.

Priority P1 – Package Hardening and Upgrades

  • Upgrade Web Server: Transition from legacy lighttpd/1.4.28 to the latest security-hardened stable release.
  • Harden SSH Daemon: Disable weak algorithms (CBC ciphers, HMAC-MD5, HMAC-SHA1) in /etc/ssh/sshd_config. Mandate public-key authentication.
  • Enable Transport Security: Setup HTTPS using TLS 1.3, configure valid certificates, and append transport protection headers (HSTS, CSP, X-Content-Type-Options).
